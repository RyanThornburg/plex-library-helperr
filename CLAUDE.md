# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Uses [uv](https://github.com/astral-sh/uv) and Python 3.14+.

```bash
uv sync                                   # install deps (incl. dev group: pytest)
uv run main.py                            # run movers/profilers (needs HELPERR_SECRET_KEY, reads the web app's db)
uv run main.py --remove                   # run removers only (plans, never deletes)
uv run main.py --empty-trash              # empty plex library trash only
uv run main.py --serve                    # web app (needs CF_ACCESS_*, ALLOWED_EMAILS and HELPERR_SECRET_KEY env)
uv run pytest tests/ -v                   # all tests
uv run pytest tests/test_main.py::TestRunArr -v   # single test class
```

No linter/formatter is configured in `pyproject.toml`.

## What it does

A one-shot script that reads every movie (Radarr) / series (Sonarr), applies user-defined rules from the config stored in the web app's SQLite database (edited on its Settings pages; `config.toml` is only imported once), and issues bulk edits back to the *arr API. Three rule types:

- **Movers** — change root folder (with `move_files=True`) for media matching genre/tag/studio/network/certification filters; optionally tag moved items, then scan the old and new folders via Autoscan (or, without Autoscan, refresh the target Plex library).
- **Profilers** — assign a quality profile (and optionally set `monitored`) for media matched by title/studio/network.
- **Removers** (`--remove`) — Sonarr: unmonitor then delete stale seasons/episode files from tagged series, keeping the latest `keep` seasons/episodes. Radarr: delete old movies (with their files) from a root folder. Runs instead of movers/profilers, never uses `filter_time`.
- **Empty trash** (`--empty-trash`) — empties Plex library trash (the server has auto-empty off). Movers/removers only trigger scans, so this is scheduled separately, after scans finish.

`dry_run` should be assumed on when testing against a real library.

## Architecture

- `results.py` — `JobResult` (the `Change`s a job made, `scan_dirs`/`plex_libraries` left to scan, `errors` that stopped part of the job, and for removers the `removals` planned: a `PlannedRemoval` per series or movie (`service` SONARR/RADARR, `media_id`; runs stored before Radarr removers have `series_id` and no `service`, `web.jobs.removal_key()` reads both) with its file ids/paths, which the UI approves) is passed into `run_arr`, `run_removers` and `empty_plex_trash` and filled as they go, so changes made before an exception are kept. A `Change` is one bulk edit / series removal / library trash / scan with a status: `done`, `dry_run`, `blocked` (a safety check such as `max_deletes`, `max_items` or a scan in progress) or `failed`. Results carry what the future API/UI acts on; why media was skipped stays in the log. Never put URLs or secrets in a `Change`, results will be stored and shown in the UI.
- `main.py` — all rule-matching logic, `run_job(job, settings) -> JobResult` (jobs: `movers` = movers and profilers, `removers`, `empty_trash`), which the API will call, and `main()`, which parses args, runs one job and logs its summary. Run as a script it exits 1 when the result has errors or failed changes. Any exception in one arr, the scan step or empty trash becomes an error in the result (the other arr still runs, and what was already done stays recorded, so empty trash can match removed files). arrapi clients come from `arr_client.arr_api()`, whose session has a timeout (arrapi has none, a hung arr held the job runner). Radarr and Sonarr share one code path via the `arr_dispatch` table, which maps each to its arrapi class and method names (`all_movies`/`all_series`, `edit_multiple_movies`/`edit_multiple_series`) called through `getattr`. Per-instance work lives in `run_arr()`; `run_job()` catches `ArrException` per instance so one failure doesn't stop the other. When adding *arr-specific behavior, branch on `log_name` ("RADARR"/"SONARR") or extend that tuple rather than duplicating the loop.
- Matching functions (`get_matches_based_on_mover_rules`, `get_media_matching_profile_rules`) are pure: they take media lists and return the matching `Movie`/`Series` objects, which are passed directly to `edit_multiple_*`; all API side effects stay in `run_arr()`. Tests exercise these functions with `MagicMock` media objects (see helpers at the top of `tests/test_main.py`).
- Mover evaluation order: skip media already under `path` or any `exclude_paths` → apply excludes (tags, genres, certifications) → require each configured filter (studio, network, certification, genre with `genre_match`, tag with `tag_match`). All comparisons are `casefold()`ed. Movers run in config order and media matched by an earlier mover is skipped by later ones (first match wins).
- `config/__init__.py` — `build_config(document)` turns a config document (config.toml's shape as a dict) into dataclasses in `config/models.py`, raising ValueError with a TOML-style label (`[[radarr.movers]] #2: ...`). Every duration (`filter_time`, remover `min_age`/`skip_if_watched_within`, `[web]`) is parsed strictly by `parse_duration()` and raises on a bad value, so a typo can never mean "delete now" or "move the whole library"; `format_duration()` writes them back. `[settings].dry_run` is the default for each *arr section and `[plex.empty_trash]`, which may override it; a document without it is dry (config.toml without it was live, so the import writes it explicitly). `[web]` holds the web app's defaults (`WebDefaults`: follow-up delay/attempts/lookback, plan max age, `min_free_gb` for health checks). `filter_time` becomes a `timedelta`; media is filtered by `added` against naive UTC now. `config_toml_path()`/`read_toml()` are only used to import config.toml.
- `config/document.py` — the stored document: `SECRET_FIELDS` (`radarr.apikey`, `sonarr.apikey`, `plex.token`, `tautulli.apikey`, `seerr.apikey`, `sabnzbd.apikey`, `bazarr.apikey`, `autoscan.password`) are kept out of it (`strip_secrets`/`with_secrets`), `canonical()` validates and rewrites rules via `rule_to_dict()` (defaults and empties dropped, durations as `7d`), so diffs stay clean. `from_toml()` imports a config.toml and drops `remover_settings.dry_run` (noted when it was false).
- `config/models.py` — dataclasses validate in `__post_init__` (movers/profilers need at least one matching criterion; `*_match` must be `any`/`all`). `_validate_rules` in `config/__init__.py` rejects `networks` on Radarr and `studios` on Sonarr rules. `[[radarr.removers]]` are `MovieRemoverRule`s (root folder `path`, `min_age`, watch options), `[[sonarr.removers]]` `RemoverRule`s; `config.document.rule_class(arr, kind)` picks the class. Custom `__repr__`s omit empty fields and mask `apikey`/`token` because the full config is logged at startup — keep secrets masked when adding fields.
- `remover.py` — `run_removers()` plans every series first, then acts. arrapi has no episode endpoints, so `SonarrEpisodes` calls `/api/v3` directly with `requests` (episodes, episodefile, queue/details, `PUT episode/monitor`, `DELETE episodefile/bulk`). `plan_series_removal()` is pure and is where the rules live:
  - Candidates are everything outside the keep window. Only numbered seasons/episodes **with files** count toward `keep`; specials (season 0) never count and are only removable with `include_specials`.
  - `seasons` mode is all or nothing: a season is removed only if every file's `episodeFile.dateAdded` is older than `min_age`. `episodes` mode works per file; a multi-episode file holding any kept episode is kept.
  - Watch protection (`skip_if_watched_within`) only counts recent plays of removal *candidates* (watching the latest episodes never blocks) and protects from the earliest watched candidate onward. It runs before the age filter, so watching a new season still protects older seasons after it. A watched special protects only specials.
  - Series-level skips: `series.added` newer than `min_age`, anything in the download queue, or invalid/missing Sonarr data (`InvalidSeriesData`). Bad data is logged and skipped, never guessed at.
  - A series tagged for two removers is logged as an error and skipped; a tag shared between removers is rejected at config load.
  - Removers have no `dry_run`: they only delete approved removals (a reviewed plan, or auto-approve), everything else is planned for review with status `dry_run`. `max_deletes` is all-or-nothing for the files a run deletes (removals only planned for review don't count). Episodes are unmonitored before files are deleted; if unmonitoring fails the delete is skipped.
  - A `RemovalPlan` holds `Unit`s (a season, or an episode file); `labels`/`file_ids`/`episode_ids`/`dirs` derive from them. Every plan is recorded in `result.removals`.
  - Applying a reviewed plan is `run_removers(..., approved={series_id: {file_ids}})`: only those series are planned again from fresh data (same skips), `RemovalPlan.restricted_to()` keeps only units whose every file was approved (so a season with a replaced file is kept whole, and newly eligible units aren't removed), and whatever isn't removed is reported as a `blocked` change. `max_deletes` still applies.
  - Auto-approve: `run_removers(..., auto_approve=frozenset(rule keys))` deletes those rules' removals, the rest are planned for review. `RemoverRule.key` (tags casefolded, sorted, comma joined; removers can't share tags) identifies a rule outside the config document.
- `movie_remover.py` — Radarr removers, `run_movie_removers()`, run by `main.run_all_removers()` after Sonarr's (applying a plan only touches the arrs it approved media of; Radarr without removers is skipped quietly). `RadarrMovies` calls `/api/v3` with `requests` (arrapi's Movie has no `releaseDate` or file). `parse_movie()` validates (`InvalidMovieData`, never guessed; Radarr's `0001-01-01` dates are no date). A movie belongs to the rule whose `path` is its root folder (one rule per folder, `MovieRemoverRule.key` = `radarr:<root>`, so auto-approve keys never clash with Sonarr's tag keys). Pure checks: `age_skip_reason()` (no file, excluded tag, `added` and `releaseDate` both older than `min_age`, not queued) then `watch_skip_reason()` (`skip_if_ever_watched` / `skip_if_watched_within`; unknown plays keep the movie). Plays come from a `PlayLookup` (`movie_plays` kwarg of `run_job`), only for candidates of rules that check plays; in the web app it's `web.stats.movie_play_lookup()`: copies new Tautulli plays (`sync_plays`), finds the movie in Plex by tmdb/imdb guid (`PlexIndex(plex, ("movie",))`) and reads the `plays` table by its Plex guid and legacy agent guids (`movie_guids()`). A movie Plex doesn't have is left out (unknown). The CLI has no lookup, so those rules keep everything. Same plan/review/auto-approve/`max_deletes` flow as Sonarr removers; applying a plan removes a movie only if its file id is the approved one. Deleting is `DELETE movie/{id}?deleteFiles=true` (no import exclusion); the movie's folder goes to `scan_dirs`.
- `watch_history.py` — `WatchEvent`s (naive UTC) from Tautulli `get_history` (includes partial plays and all users, show TVDB id from `get_metadata` guids), falling back to Plex server history (completed plays only). Returns `None` on failure, and removers with `skip_if_watched_within` are then skipped. Events are matched to series by TVDB id, and by title only when the history has no TVDB id. Tautulli's `apikey` is a query param, so `requests` error text contains it: redact it before logging or storing any Tautulli error.
- `autoscan.py` — POSTs the old and new folders of moved media to Autoscan's `/triggers/manual`. Paths are sent as the *arr sees them; the rewrite on Autoscan's Plex target maps them to Plex paths and its `minimum-age` covers the async move.
- `plex.py` — fallback when Autoscan isn't configured: connects via plexapi and refreshes each library section collected from executed (non-dry-run) movers. Also `empty_plex_trash()` for `--empty-trash`: counts each movie/show section's trash via `/library/sections/{key}/all?type=<movie|episode>&trash=1` (includes old versions left by upgrades) and skips a section that is `refreshing` or over `[plex.empty_trash].max_items`, which guards against a missing mount trashing a whole library. Only then `list_trash()` fetches the items: Plex marks each trashed version (`Media`) with `deletedAt`, so an item with a live version is an upgrade leftover (only counted) and one without is fully deleted (`TrashedItem` in `result.trash`, listed on the run page). Fully deleted items are matched to the web app's removers by file name (`removed_files`, from `JobRunner.removed_files()`; sonarr and plex paths differ), and only unmatched ones count toward `max_deleted_items`. Its `dry_run` defaults to `[settings].dry_run`.
- `web/` — FastAPI app run by `main.py --serve` (one uvicorn worker on purpose: the scheduler will live in-process, no Redis). `create_app(settings, keys, run_job, load_config, run_scheduler, lookups)` is a factory; tests pass `keys` to replace the team's signing keys.
  - `config_store.py` — `ConfigStore`: the config is `ConfigVersion` rows (`config_versions`, the newest is current; a restore saves an old document again) plus `ConfigSecret` rows (`config_secrets`, encrypted by `secret_box.SecretBox` with `HELPERR_SECRET_KEY` via HKDF + Fernet, never versioned, never rendered: forms are write-only, empty keeps the saved one). `save(document, by, note, expected_version, secrets)` validates (with stand-in secrets), raises `ConfigConflict` when `expected_version` (0 = none yet, None = skip) isn't current, and turns auto-approve off for remover rules it changes or removes (noted in the version). `load_settings()` is what jobs run with (`app.state.load_config` unless a test passes one); an undecryptable secret raises `SecretError` saying to re-enter it. `web_defaults()` reads `[web]` without secrets, for the scheduler and plan expiry. `import_toml()` imports config.toml (at `config_toml_path()`) only when there's no version yet; at startup its error is kept in `app.state.import_error` and shown on Settings → General. `open_store()` is the CLI's way in (`main.load_settings()`): same db, migrations and import.
  - `lookups.py` — `Lookups` caches (10 min, cleared when a connection is saved) each arr's `ArrLibrary` (media `snapshot()`s, root folders, profiles, tag labels) and Plex's libraries, for the rule forms' pick lists and `preview_mover()`/`preview_profiler()` (whole library, earlier movers claim first, counts what's within `filter_time`; logs of `main` are silenced for that thread by `quiet()`). Snapshots matter: arrapi objects reload themselves from the api when an empty field is read (no certification) and tags/quality profiles only hold an id until read, one request per movie, so `snapshot()` reads fields with `object.__getattribute__` and resolves tags/profiles from the fetched lists. `check_connection()` backs the Test buttons. Error text goes through `redact()` (Tautulli's key is a query param).
  - `settings.py` reads `CF_ACCESS_TEAM_DOMAIN`, `CF_ACCESS_AUD`, `ALLOWED_EMAILS` and `HELPERR_SECRET_KEY` (32+ chars, encrypts the config's secrets) and refuses to start if any is missing or malformed, so auth can never be half configured. Optional `REMOVERS_ALLOW_APPLY` (`true`/`false`, default off) must be one of those when set.
  - `auth.py` is pure ASGI middleware that wraps every route (static files and 404s too) except `PUBLIC_PATHS` (`/healthz`) and `API_KEY_PATHS` (exact paths, `/webhooks/arr`), which check the app's API key themselves. It verifies `Cf-Access-Jwt-Assertion` (RS256 only, keys from `https://<team>/cdn-cgi/access/certs`, issuer, audience, exp), then the email against `ALLOWED_EMAILS`. Denial reasons are logged, never returned. Fails closed, including when Cloudflare's keys can't be fetched.
  - `security.py` adds a strict CSP (no inline scripts/styles, no third-party content, so self-host any JS such as htmx) and other headers, and rejects non-GET requests whose `Origin` doesn't match `Host` (CSRF). It runs before auth. `API_KEY_PATHS` skip the Origin check, since they carry no browser cookies.
  - `jobs.py` — `JobRunner`: one worker thread runs queued `JobRun`s in order, so jobs never overlap (no locks needed). `submit()` refuses a job that is already queued/running (`AlreadyActive`). Each run calls `load_config()` (the store) fresh and then `main.run_job()`, with `config.force_dry_run()` when the run asked for dry run. A run can only force dry run on; making the config live is a settings change, which goes through a confirmation (`settings_routes.turns_live()`). Removers delete through `submit_apply()`, applying a reviewed removers plan (`JobRun.plan_run_id`, `approved`: `[{service, media_id, title, file_ids}]`, selected by `removal_key()` = `sonarr:<id>`/`radarr:<id>`, passed to `run_job` as `{"SONARR": {id: files}, "RADARR": ...}`). A removers run gets `movie_plays` only when Radarr has removers (`JobRunner(movie_plays=)` lets tests replace it). It needs `REMOVERS_ALLOW_APPLY=true` (`WebSettings.allow_remover_apply`, an env var so the UI can never turn it on, checked again when the run executes), a finished non-apply removers run whose `approvable()` removals (`dry_run`/`blocked`) include every selected series, the plan under `WebDefaults.plan_max_age` (`defaults()`, 7 days by default), and no earlier apply of that plan. `apply_problem()` says why not; pages show it. Auto-approve is the other: `RemoverRuleSetting` rows (`remover_rule_settings`, keyed by `RemoverRule.key`) set on the Removers page; `auto_approved_rules()` returns their keys only when `allow_apply`, and `_execute` passes them as `auto_approve` only for a removers run that isn't forced dry and isn't applying a plan, so forced dry runs never delete. `routes.config_modes()` reports removers as partly live (None) when auto-approved rules would delete, so the job card, Run… confirmation and schedule form say so. `RunLogCapture` stores that run's log lines, filtered to the worker thread so request logs don't leak in. At startup, runs left queued/running are marked failed and never resumed (removers delete files). `wait_idle()` is for tests.
  - `scheduler.py` — `Scheduler` thread wakes a second into every minute and `tick(now)`s: each enabled `Schedule` whose cron has matched since `max(last_fired_at, updated_at, started_at)` is submitted to the `JobRunner` (trigger `schedule`, `JobRun.schedule_id` set). So missed times fire at most once, never for times before the app started or the schedule was last edited (an edit resets it). `last_fired_at` is written before submitting; an `AlreadyActive` job skips that time. Tests pass `run_scheduler=False` to `create_app` and call `tick()` directly. Schedules are stored only in the database.
  - The scheduler also queues a follow-up empty trash (trigger `followup`) via `trash_followup_due()`, worked out from run history and `TrashEvent`s (`trash_events`, upgrades the webhook recorded) only: `followup_delay` after the last "work" (a live movers/removers run with a `done` move/remove, or an upgrade) not covered by the last `emptied()` run (config settings, nothing blocked/failed; a forced dry run doesn't count, a config-dry one does). An empty trash only covers work from `followup_delay` before it started, since Plex may not have scanned later work yet. A steady stream of work can delay it at most `FOLLOWUP_MAX_WAIT` delays after the first work since the last follow-up. Retried up to `followup_attempts` (0 = off), looking back `followup_lookback`, all from `WebDefaults` via `runner.defaults()`.
  - `webhooks.py` — `POST /webhooks/arr` for Radarr/Sonarr connect webhooks. `MovieAdded`/`SeriesAdd` call `JobRunner.submit_soon("movers", "webhook", "Radarr: Title (Year)")`, which reuses a queued run, or queues one more after a running one (`_rerun`), so adds close together share a run. `Download` with `isUpgrade` (On File Upgrade) records a `TrashEvent` (pruned after `followup_lookback`) for the follow-up empty trash, never runs anything itself (Plex hasn't scanned yet). Other events return 200 and do nothing (so Radarr's Test works). The key comes from `X-Api-Key` or the basic auth password, never the URL, compared with `hmac.compare_digest`. The app's API key is an `AppSetting` (`app_settings` key/value table, also for future UI-edited defaults), generated at startup when missing and shown in plain text on `/settings/webhook` like the *arrs, since it only starts movers. A key that unlocks more (e.g. the JSON API, which can approve deletes) should get separate keys with explicit scopes, not this one.
  - `stats.py` — request stats, read-only against the services. `StatsSync` is its own thread (subclassed by `playback.PlaybackSync`) (started with the scheduler, at startup, every `SYNC_INTERVAL` and on `sync_now()`), not a `JobRunner` job, so the first sync (all of Tautulli's history, ~180k plays, a few minutes) never holds up movers. `sync_plays()` upserts Tautulli `get_history` rows (oldest first, from a day before the newest stored play; plays in progress have no id and are skipped) into `plays` (`Play`, also keeps transcode decision/platform/player for later stats). `sync_requests()` rewrites `media_requests` (`MediaRequest`): every Seerr request (`parse_request()`), its requester matched to a Tautulli user (`match_user()`: plex id, then username, then email), its items found in Plex by tmdb/tvdb guid (`PlexIndex`, one `search(includeGuids=True)` per movie/show section), and `summarize()`d from its plays. `wanted()` says what counts and `find_plays()` finds them: by **Plex guid** (`plex://movie/…`, `plex://episode/…`, which survives a move to another library where rating keys don't), by legacy agent guid built from the item's tmdb/imdb/tvdb ids (plays before late 2021 have `com.plexapp.agents.thetvdb://121361/6/1`; `normalize_guid()` drops `?lang=`), and a show's also by its rating key or legacy tvdb prefix, so episodes removers deleted still count. Plays carry season/episode, filtered to the requested seasons (every numbered season when none are named). `watched`/`started` count only episodes Plex has now (an episode in two libraries once), `requester_plays` counts any; `progress()` treats any requester play as started. Titles come from Plex, then the previous sync, then Seerr's TMDB details. The last sync's `SyncStatus` (errors redacted) is an `AppSetting`.
  - `stats_routes.py` — `/requests` (per-requester table and filtered request list; `progress()` is `finished`/`started`/`not_started`, or `unavailable` (not in Plex) / `unmatched` (no Tautulli user)), `POST /requests/sync`, `GET /api/requests` and `/api/requests/users` (filters `user`, `type`, `progress`, `min_days` = days in Plex, and `period` of `requested_at`: `PERIODS`, default `year` = since 1 January UTC, `custom` with `since`/`until` dates (until inclusive), resolved by `period_range()`; 422 when invalid). The users table uses `Filters.in_scope()` (period, type, requester), the list all of them, the first `REQUESTS_SHOWN` unless `?all=1`. Requests and Playback name the connections they're missing (`routes.missing_connections()`). Tests that don't test the period pass `period=all`, so they don't break in January.
  - `playback.py` — playback quality, its own `PlaybackSync` thread (a `StatsSync` subclass with its own `interval`, `status_key` and `sync()`; started with the scheduler, every `INTERVAL` = 10 min and on `sync_now()`). `playbacks` (`Playback`) holds movie/episode plays for `KEEP` (a year). The user cares where problems happen now, so it never reads old history: the first sync reads `BACKFILL` (30 days), later ones from a day before the newest stored play. `sync_playbacks()` reads `get_history` newest first and, for each play not stored yet, `get_stream_data` (`stream_data()`: None when Tautulli answers 400 or an error, the play is then kept with `details=False` and never retried). `causes()` is pure and says why a play transcoded, main cause first: a quality limit (`quality_profile` not Original) transcodes any file, so the video's format/HDR/resolution only count at Original (the user agreed); audio only counts when the video wasn't transcoded; `unknown` otherwise. `report()` (page and `GET /api/playback`) leads with `fixes()`: transcodes grouped by person and device (a setting lives on one app on one device), worst first, each with its main cause, current value (quality limit or file format) and what to change (`CHANGES`), stopping at `FIXES` devices, at `FIXES_COVER` of the transcodes or below `FIX_MIN_TRANSCODES`; the page shows that list and folds the rest (`<details class="fold">`, closed). It also counts decisions, main causes with `CAUSES` hints, users and players (transcode rate, most common `quality_limit` and `file_format`, latest play), `formats` (per `file_format()` of a `FILE_CAUSES` cause: all plays of it, those it made transcode, users, players) and `files` (the same file transcoding for `FILE_MIN_USERS`+ people). Its status is `SyncStatus` under `playback_sync` (`sync_status(engine, key)`).
  - `playback_routes.py` — `/playback` (`window` = `WINDOWS` key `24h`…`365d`, default `7d`; `user` = Plex user id; 422 when invalid), `POST /playback/sync`, `GET /api/playback`.
  - `status.py` — `check_all(settings, now)`: what Plex (through Tautulli's `server_status`/`get_activity`), Radarr/Sonarr (`health`, `queue` with movie/series, `wanted/missing`/`wanted/cutoff` counts, `rootfolder`), SABnzbd (`queue`, failed `history` within `SAB_FAILED_WITHIN`, `warnings`), Bazarr (`system/status`, `badges`, `system/health`, `providers` under its base url with `X-API-KEY`; `bazarr_answers()` is pure: health issues, throttled providers and a `DOWN` signalr for an arr it uses are warnings; without the base url it answers its web page, `BAZARR_NOT_API`) and Seerr (`status`, `request/count`, `issue/count`) report now, each a `ServiceStatus` (`state` ok/warn/bad/off, `facts`, `problems`, `items`). Read only, no cache, every service asked at once in threads; `_checked()` turns one failing into that card's `error` with every configured key redacted (SABnzbd's and Tautulli's keys are query params). The parsers (`arr_queue`, `sab_queue`, `stream`…) are pure, tests feed them dicts. A queue record needs attention (`stuck_level()`) when its `trackedDownloadState` is in `STUCK_STATES` or its status is warning/error. A transcode marks its row, not the Plex card. The one write: `ArrQueue` lists stuck records grouped per download (`stuck_downloads()`, keyed by `downloadId`; a season pack is a record per episode) and removes them with `DELETE queue/bulk` (`REMOVAL_METHODS` client/ignore → `removeFromClient`, `BLOCKLIST` none/search/only → `blocklist`/`skipRedownload`). The arrs look every id up before removing anything and 404 when one is gone, so `clear_stuck()` re-reads the queue and sends only the selected downloads still stuck. `failure()` turns a request error into redacted text (also used by `_checked()`).
  - `health.py` — health checks: `HealthMonitor` (a `StatsSync` subclass, every `CHECK_INTERVAL` = 5 min, started with the scheduler) runs `status.check_all()` and `record()`s each problem as a `HealthIncident` (`health_incidents`: started, last seen, ended, worst level, latest text), kept for `KEEP` (a year). `issues()` turns a `ServiceStatus` into what's recorded: an `error` is a `down` incident only, and that service's other incidents stay open (nobody knows if they cleared); warn/bad problems by `Problem.key` (set where the text changes: counts, countdowns, `disk:<where>`, `failed:<nzo_id>`) or their text; radarr/sonarr stuck queue items as `queue:<title>` (plex's items are streams, not problems); Seerr's `pending`/`issues` are `NOT_RECORDED` (work, not faults; pending is an `info` note, so it never makes the card a warning). `problem_key()`/`item_key()` are the incident keys, also used by the status page to show how long each open problem has lasted. A problem gone for at most `REOPEN_WITHIN` (15 min) continues its incident. An `off` service clears its incidents. `status.ServiceStatus.low_space()` adds low disk space problems from `[web] min_free_gb` (0 off) for *arr root folders and SABnzbd's incomplete/complete folders. Its status is a `SyncStatus` under `health_check`.
  - `status_routes.py` — `/status` (a one-line verdict linking to each service that needs you, a card per warn/bad service with its problems first and how long each has lasted (from ongoing incidents), healthy and unconnected services as one `<details>` line each in one panel (unconnected ones link to their Connections form), then the last 7 days' incidents, ongoing first; `<meta refresh>` every minute, `?refresh=0` pauses it). Each service links to its web UI (`links()`: the connection's `public_url`, else its local url; plex's is Tautulli's), other tools from `[[links]]` (`LinkConfig`: name, url and/or public_url, optional `service` from `LINK_SERVICES`, edited on Settings → Connections, `POST /settings/links` add/remove) sit next to that service's link, or under the services without one; `static/app.js` switches links to the local url when the browser chose it, and mutes warn/bad problems (`data-mute` = `service|health.problem_key()`), both in `localStorage`. A mute is dropped once its service's problems are all on the page without it (it cleared); a card with everything muted goes neutral and leaves the verdict. Cards that are down, have stuck downloads or more than `MAX_PROBLEMS` are `data-unmutable` and `GET /api/status` (503 when the settings can't load), `/status/history` and `GET /api/status/history` (`days` in `HISTORY_DAYS`, default 30; `service`; 422 when invalid) with a per-service summary (`health.summary()`: incidents, ongoing, down time within the period). Tests monkeypatch `web.status_routes.check_all`. Stuck downloads: `/status/{radarr,sonarr}/queue` (linked from the card; its own page because `/status` refreshes and would drop the checkboxes), `POST /status/{service}/queue/remove` (form `download` repeated, `method`, `blocklist`; read with `routes.form_lists()`, redirects with `removed`/`gone`), `GET /api/status/{service}/queue`, `POST /api/status/{service}/queue/remove` (`{downloads, method, blocklist}`; 409 not connected, 502 arr failure). A removal is logged with who did it and wakes the health check (`sync_now()`). Not behind `REMOVERS_ALLOW_APPLY`: it removes downloads, not library media.
  - `cron.py` — own 5-field parser (no dependency): numbers, `*`, ranges, steps, lists, `@hourly` etc. Each `Schedule` has an IANA `timezone` (`parse_zone()`, `tzdata` is a dependency so the image's zoneinfo doesn't matter) and `next_after_utc(after, zone)` matches the cron's wall time there, converting from/to naive UTC; the container's TZ is never used. Day and weekday are OR'ed when both are restricted, like cron. `parse()` raises ValueError naming the bad field, and rejects expressions that never run.
  - `config.force_dry_run()` must turn on every `dry_run` in the settings; `tests/test_jobs.py` walks the settings tree to catch a new one being missed. `config.config_dry_run(job, settings)` says whether a job as configured is dry (None = mixed between arrs).
  - Errors: `app.add_error_pages()` renders a page's 404/422/409 as `error.html` (`routes.error_page()`, with a way back) for browser requests, the JSON API keeps FastAPI's JSON; an id too large for SQLite (`OverflowError`) is a 404. `build_config` raises ValueError for wrongly shaped sections, so forms and `PUT /api/config` never 500.
  - `routes.py` — pages: `/` redirects to `/status` (the landing page), `/runs` (job cards with the config's dry run state, recent runs, `?before=<id>` pages back `RUNS_PAGE` at a time; Run while that job is active lands on it with `?busy=1`, which says so; Apply then answers 409 on the confirm page), `GET /jobs/{job}/confirm` (every non-forced run goes through this page, which says whether it's live; there's no JS `confirm()` under the CSP), `POST /jobs/{job}?dry_run=` (query param), `/runs/{id}` (refreshes with `<meta refresh>` while active; a removers run lists its `removals` with checkboxes when approvable, and leaves those out of its changes table), `GET /runs/{id}/apply?item=` (confirmation with each arr's file total and its `max_deletes`) and `POST /runs/{id}/apply?item=` (query params again), `/schedules` (list, pause/resume), `/schedules/new` (its time zone select is set to the browser's zone by `static/app.js`) and `/schedules/{id}` (form; POSTs go to `/schedules`, `/schedules/{id}`, `/schedules/{id}/toggle`, `/schedules/{id}/delete`). Form bodies are parsed by `form_fields()` (last value of each field; `form_lists()` keeps them all) with `parse_qs`, capped at `MAX_FORM_BYTES`, so no python-multipart; unchecked checkboxes are absent. JSON API: `POST /api/jobs/{job}` (`{"dry_run": true}` by default, 409 when active), `GET /api/runs`, `GET /api/runs/{id}`, `GET/POST /api/schedules`, `GET/PUT/DELETE /api/schedules/{id}` (422 with `errors` when invalid), `POST /api/runs/{id}/apply` (`{"items": ["sonarr:1", "radarr:2"]}`, or `{"series_ids": [...]}` for Sonarr, 422 with `error` when refused), `/removers` (config's remover rules with an auto-approve switch; turning on goes through `GET /removers/auto-approve?rule=`, then `POST /removers/auto-approve?rule=&enabled=`), `GET /api/removers`, `POST /api/removers/auto-approve` (`{"rule", "enabled"}`; turning on needs the rule in the config, turning off doesn't), and `/removers` links to the rule editor. New schedules default to dry run in both the form and the API. Schedules are validated by `scheduler.schedule_errors()`. `requested_by` is the Access email. Templates read results as dicts: use `change["items"]`, since `change.items` is the dict method.
  - `settings_routes.py` — Settings pages (sub-nav in `templates/settings/_layout.html`, field macros in `_fields.html`): `/settings` (general + `[web]` defaults + import status), `/settings/connections` (one form per service, `action=save|test|disconnect`), `/settings/{radarr,sonarr}` (dry run/tag, movers and profilers tables; registered last so `/settings/{arr}` doesn't catch `/settings/trash`), rule forms `/settings/{arr}/{movers,profilers,removers}/{new,n}` (removers edited from `/removers`; Radarr's use `movie_remover_form.html`, whose `watched` select (always/ever/within) becomes `skip_if_ever_watched`/`skip_if_watched_within`; `action=preview` renders matches, saves nothing), `.../{n}/delete`, `.../{n}/move?direction=`, `/settings/{arr}/remover-settings`, `/settings/trash`, `/settings/webhook` (API key, `POST /settings/api-key`), `/settings/history` (`?before=<id>` pages back `HISTORY_PAGE` at a time) and `/settings/history/{id}` (unified diff of the JSON, restore). Rule forms carry `loaded`, a `fingerprint()` of the rule they opened; saving or deleting by number is refused when the rule there changed (another tab deleted or moved one). Settings forms take up to `MAX_SETTINGS_FORM_BYTES`. Every form carries the `version` it was loaded at. `commit()` saves, re-renders on `ConfigConflict`/ValueError, and sends a change that takes movers or empty trash off dry run (`turns_live()`) through `settings/confirm_live.html`, which re-posts the fields with `confirm_live=1`; connection and rule saves skip that check (they don't change dry run). List fields are textareas, one value per line, which `static/app.js` turns into chips with `<datalist>` suggestions. JSON: `GET /api/config` (document, version, secret names/readability), `PUT /api/config` (`{version, config, confirm_live}`; 409 stale, 422 invalid, secrets refused, live without confirm refused), `GET /api/config/versions`, `GET /api/config/versions/{id}`, `POST /api/config/versions/{id}/restore`.
  - Tests call `create_app(settings, keys, run_job, load_config)` with fakes, or without `load_config` to use the real store with a fake `lookups` (`tests/test_settings_web.py`), so no test calls an arr. `tests/conftest.py` points `DATA_DIR` at each test's tmp dir, so the startup import never reads the real config/config.toml.
  - The web app logs to `logs/web.log` (`logging_config("web.log")`), separate from the CLI's `log.log`, since they run in different containers and two processes rotating one file lose lines.
  - `db.py` uses SQLite at `$DATA_DIR/helperr.db` (WAL, foreign keys, busy timeout). Schema changes go through Alembic migrations in `web/migrations/versions`, applied at startup. Generate new ones with autogenerate against a scratch db, then tidy them.
  - The `localtime` filter renders `<time datetime="...Z">... UTC</time>`, which `static/app.js` rewrites in the browser's time zone; there's no server-side time zone. `localdate` (`data-date`) shows only the date, for dense tables, with the full time in its title.
  - Templates link assets root-relative (`/static/...`). Never use `url_for` for URLs: behind cloudflared the app sees `http`, so absolute URLs would be mixed content.
  - No interactive API docs (`/docs`, `/openapi.json`); they would be one more surface to protect.
- `logging_config.py` — `SecretFilter` on every handler (and each run's `RunLogCapture`) redacts the config's secrets from messages and tracebacks: `ConfigStore.load_settings()` registers them with `hide_secrets()` (raw and percent-encoded), `redacted()` is used for error text stored in results, and `jobs.hide_in()` redacts a stored run result. arrapi puts `?apikey=` in its errors, so arr failures are logged without a traceback (`main.failed()`). dictConfig with a Rich console handler (`markup=False`, so titles with brackets render literally) and a rotating plain-text file at `logs/log.log`. Log lines are prefixed with `log_name` and a tab.

## Notes

- Code uses Python 3.14 syntax, e.g. unparenthesized multi-exception `except A, B:` in `plex.py` (PEP 758) — this is intentional, not a bug.
- `main()` takes `argv` (tests call `main.main([])` so pytest's argv isn't parsed).
- `config/config.toml` holds real credentials and is gitignored; it's only read to import it into the database. New settings go in the document (and a settings form), not TOML-only; keep `config.toml.example` and the README config tables in sync when adding fields, and add a secret to `SECRET_FIELDS` (plus a masked `__repr__`).
- `DATA_DIR` (set to `/config` in the Dockerfile) moves `helperr.db`, `config.toml` and `logs/` out of the code dirs; unset, they stay at the repo root, `config/config.toml` and `logs/`. Docker can't mount over `/app/config` because that's the config Python package.
- `.github/workflows/docker.yml` runs the tests, then builds the image; pushes to `mainline` publish `ghcr.io/ryanthornburg/plex-library-helperr` (`latest` and `sha-<commit>`), and pushes to `v2` publish `v2` and `sha-<commit>`; Unraid's web container pulls `v2`.
- Branches: `mainline` is the script-only version (v1); the web app lives on `v2` until it's ready to merge back. `mainline` reverted the web commits (no force push), and `v2` merged that revert with `-s ours`, so merging either way later works: script fixes go `mainline` → `v2` with a plain merge, and `v2` merges into `mainline` without reverting the revert. Actions are pinned to commit SHAs (with the version in a comment) and Dependabot updates them along with uv and the base images.
- `.dockerignore` is an allowlist so `config/config.toml` never reaches the build context. When adding a module outside the top level, `config/` included (each file is listed), add it there and to the Dockerfile's `COPY` lines; `web/` is copied whole. Building the image and running it `--read-only` catches a missed one.
