# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Uses [uv](https://github.com/astral-sh/uv) and Python 3.14+.

```bash
uv sync                                   # install deps (incl. dev group: pytest)
uv run main.py                            # run movers/profilers (needs HELPERR_SECRET_KEY, reads the web app's db)
uv run main.py --remove                   # run removers only (plans, never deletes)
uv run main.py --empty-trash              # empty plex library trash only
uv run main.py --serve                    # web app (needs HELPERR_SECRET_KEY; AUTH_MODE=cloudflare also CF_ACCESS_* and ALLOWED_EMAILS)
uv run main.py --reset-login              # forgotten password: delete the login, sign everyone out, print a setup token
uv run pytest tests/ -v                   # all tests
uv run pytest tests/test_main.py::TestRunArr -v   # single test class
```

No linter/formatter is configured in `pyproject.toml`.

## What it does

A one-shot script that reads every movie (Radarr) / series (Sonarr), applies user-defined rules from the config stored in the web app's SQLite database (edited on its Settings pages), and issues bulk edits back to the *arr API. Three rule types:

- **Movers** — change root folder (with `move_files=True`) for media matching genre/tag/studio/network/certification filters; optionally tag moved items, then scan the old and new folders via Autoscan (or, without Autoscan, refresh the target Plex library).
- **Profilers** — assign a quality profile (and optionally set `monitored`) for media matched by title/studio/network.
- **Removers** (`--remove`) — Sonarr: unmonitor then delete stale seasons/episode files from tagged series, keeping the latest `keep` seasons/episodes. Radarr: delete old movies (with their files) from a root folder. Runs instead of movers/profilers, never uses `filter_time`.
- **Empty trash** (`--empty-trash`) — empties Plex library trash (the server has auto-empty off). Movers/removers only trigger scans, so this is scheduled separately, after scans finish.

`dry_run` should be assumed on when testing against a real library.

## Architecture

- `results.py` — `JobResult` (the `Change`s a job made, `scan_dirs`/`plex_libraries` left to scan, `errors` that stopped part of the job, and for removers the `removals` planned: a `PlannedRemoval` per series or movie (`service` SONARR/RADARR, `media_id`; `web.jobs.removal_key()` is `sonarr:<id>`/`radarr:<id>`) with its file ids/paths, which the UI approves) is passed into `run_arr`, `run_removers` and `empty_plex_trash` and filled as they go, so changes made before an exception are kept. A `Change` is one bulk edit / series removal / library trash / scan with a status: `done`, `dry_run`, `blocked` (a safety check such as `max_deletes`, `max_items` or a scan in progress) or `failed`. Results carry what the future API/UI acts on; why media was skipped stays in the log. Never put URLs or secrets in a `Change`, results will be stored and shown in the UI: a failure's text goes through `logging_config.failure_text(e)` (urls cut to their path, `?k=v`/`&k=v` parameters dropped even after a bare path, secrets redacted, connection failures in words; `status.failure()` uses it too).
- `main.py` — all rule-matching logic, `run_job(job, settings) -> JobResult` (jobs: `movers` = movers and profilers, `removers`, `empty_trash`, `clear_stuck` = `web.queue_cleanup`, web app only), which the API will call, and `main()`, which parses args, runs one job and logs its summary. Run as a script it exits 1 when the result has errors or failed changes. Any exception in one arr, the scan step or empty trash becomes an error in the result (the other arr still runs, and what was already done stays recorded, so empty trash can match removed files). arrapi clients come from `arr_client.arr_api()`, whose session has a timeout (arrapi has none, a hung arr held the job runner). Radarr and Sonarr share one code path via the `arr_dispatch` table, which maps each to its arrapi class and list method (`all_movies`/`all_series`). Media is read with `arr_client.read_media()` (`snapshot()`s: tags and quality profiles from one list each, no request per item) and edited with `arr_client.edit_media()` (`PUT movie/editor`/`series/editor` from `EDITORS[log_name]`, with the snapshots' ids: arrapi's `edit_multiple_*` reads the whole library again to check ids). Sonarr removers read series the same way. Per-instance work lives in `run_arr()`; `run_job()` catches `ArrException` per instance so one failure doesn't stop the other. When adding *arr-specific behavior, branch on `log_name` ("RADARR"/"SONARR") or extend that tuple rather than duplicating the loop.
- Matching functions (`get_matches_based_on_mover_rules`, `get_media_matching_profile_rules`) are pure: they take media lists and return the matching `Movie`/`Series` objects, whose ids go to `edit_media()`; all API side effects stay in `run_arr()`. Tests exercise these functions with `MagicMock` media objects (see helpers at the top of `tests/test_main.py`).
- Mover evaluation order: skip media already under `path` or any `exclude_paths` → apply excludes (tags, genres, certifications) → require each configured filter (studio, network, certification, genre with `genre_match`, tag with `tag_match`). All comparisons are `casefold()`ed. Movers run in config order and media matched by an earlier mover is skipped by later ones (first match wins).
- `config/__init__.py` — `build_config(document)` turns a config document (a dict of TOML-style sections) into dataclasses in `config/models.py`, raising ValueError with a TOML-style label (`[[radarr.movers]] #2: ...`). Every duration (`filter_time`, remover `min_age`/`skip_if_watched_within`, `[web]`) is parsed strictly by `parse_duration()` and raises on a bad value, so a typo can never mean "delete now" or "move the whole library" (`filter_time` must also be over 0, empty means the whole library); `format_duration()` writes them back. Every model's `__post_init__` calls `check_types()`, which checks plain fields against their annotations (bool, int, str, timedelta, lists of them): the document is json, and a string where a list belongs would be read letter by letter, a `0` dry run would be live. `[settings].dry_run` is the default for each *arr section and `[plex.empty_trash]`, which may override it; a document without it is dry. `[web]` holds the web app's defaults (`WebDefaults`: follow-up delay/attempts/lookback, plan max age, `min_free_gb` for health checks). `filter_time` becomes a `timedelta`; media is filtered by `added` against naive UTC now.
- `config/document.py` — the stored document: `SECRET_FIELDS` (`radarr.apikey`, `sonarr.apikey`, `plex.token`, `tautulli.apikey`, `seerr.apikey`, `sabnzbd.apikey`, `bazarr.apikey`, `unraid.apikey`, `autoscan.password`) are kept out of it (`with_secrets()` puts them back to build the settings, `secrets_in()` finds any that slipped in), `canonical()` validates and rewrites rules via `rule_to_dict()` (defaults and empties dropped, durations as `7d`), so diffs stay clean.
- `config/models.py` — dataclasses validate in `__post_init__` (movers/profilers need at least one matching criterion; `*_match` must be `any`/`all`). `_validate_rules` in `config/__init__.py` rejects `networks` on Radarr and `studios` on Sonarr rules. `[[radarr.removers]]` are `MovieRemoverRule`s (root folder `path`, `min_age`, watch options), `[[sonarr.removers]]` `RemoverRule`s; `config.document.rule_class(arr, kind)` picks the class. Custom `__repr__`s omit empty fields and mask `apikey`/`token` because the full config is logged at startup — keep secrets masked when adding fields.
- `removals.py` — what both removers share: `Approved`, `InvalidArrData` (`InvalidSeriesData`/`InvalidMovieData` subclass it) with `required_int()`, and `act()`, the review / auto-approve / `max_deletes` / delete tail (each remover passes its own `record`, `delete` (returns why it failed) and `removed`). Their `/api/v3` clients subclass `arr_client.ArrV3`. `utc_now()` (naive UTC) lives in `results.py`; `web.jobs` re-exports it.
- `remover.py` — `run_removers()` plans every series first, then acts. arrapi has no episode endpoints, so `SonarrEpisodes` calls `/api/v3` directly with `requests` (episodes, episodefile, queue/details, `PUT episode/monitor`, `DELETE episodefile/bulk`). `plan_series_removal()` is pure and is where the rules live:
  - Candidates are everything outside the keep window. Only numbered seasons/episodes **with files** count toward `keep`; specials (season 0) never count and are only removable with `include_specials`.
  - `seasons` mode is all or nothing: a season is removed only if every file's `episodeFile.dateAdded` is older than `min_age`. `episodes` mode works per file; a multi-episode file holding any kept episode is kept.
  - A file's age is its episodes' first import (`first_imports()` from `history/series`, read only when a candidate is too new by `dateAdded`), since Sonarr gives a file it lost and re-found (the mkv→mp4 converter, a disk dropping out) or upgraded a new `dateAdded`. A deletion for any other reason (`Manual`, i.e. a remover) resets it; episodes without an import fall back to `dateAdded` (`added_at()`, the newest episode of a multi-episode file counts).
  - Watch protection (`skip_if_watched_within`) only counts recent plays of removal *candidates* (watching the latest episodes never blocks) and protects from the earliest watched candidate onward. It runs before the age filter, so watching a new season still protects older seasons after it. A watched special protects only specials.
  - Series-level skips: `series.added` newer than `min_age`, anything in the download queue, or invalid/missing Sonarr data (`InvalidSeriesData`). Bad data is logged and skipped, never guessed at.
  - A series tagged for two removers is logged as an error and skipped; a tag shared between removers is rejected at config load.
  - Removers have no `dry_run`: they only delete approved removals (a reviewed plan, or auto-approve), everything else is planned for review with status `dry_run`. `max_deletes` is all-or-nothing for the files a run deletes (removals only planned for review don't count). Episodes are unmonitored before files are deleted; if unmonitoring fails the delete is skipped.
  - A `RemovalPlan` holds `Unit`s (a season, or an episode file); `labels`/`file_ids`/`episode_ids`/`dirs` derive from them. Every plan is recorded in `result.removals`.
  - Applying a reviewed plan is `run_removers(..., approved={series_id: {file_ids}})`: only those series are planned again from fresh data (same skips), `RemovalPlan.restricted_to()` keeps only units whose every file was approved (so a season with a replaced file is kept whole, and newly eligible units aren't removed), and whatever isn't removed is reported as a `blocked` change. `max_deletes` still applies.
  - Auto-approve: `run_removers(..., auto_approve=frozenset(rule keys))` deletes those rules' removals, the rest are planned for review. `RemoverRule.key` (tags casefolded, sorted, comma joined; removers can't share tags) identifies a rule outside the config document.
- `movie_remover.py` — Radarr removers, `run_movie_removers()`, run by `main.run_all_removers()` after Sonarr's (applying a plan only touches the arrs it approved media of; Radarr without removers is skipped quietly). `RadarrMovies` calls `/api/v3` with `requests` (arrapi's Movie has no `releaseDate` or file). `parse_movie()` validates (`InvalidMovieData`, never guessed; Radarr's `0001-01-01` dates are no date). A movie belongs to the rule whose `path` is its root folder (one rule per folder, `MovieRemoverRule.key` = `radarr:<root>`, so auto-approve keys never clash with Sonarr's tag keys). Pure checks: `age_skip_reason()` (no file, excluded tag, `added` and `releaseDate` both older than `min_age`, not queued) then `watch_skip_reason()` (`skip_if_ever_watched` / `skip_if_watched_within`; unknown plays keep the movie). Plays come from a `PlayLookup` (`movie_plays` kwarg of `run_job`), only for candidates of rules that check plays; in the web app it's `web.stats.movie_play_lookup()`: copies new Tautulli plays (`sync_plays`), finds the movie in Plex by tmdb/imdb guid (`PlexIndex(plex, ("movie",))`) and reads the `plays` table by its Plex guid and legacy agent guids (`movie_guids()`). A movie Plex doesn't have is left out (unknown). The CLI has no lookup, so those rules keep everything. Same plan/review/auto-approve/`max_deletes` flow as Sonarr removers; applying a plan removes a movie only if its file id is the approved one. Deleting is `DELETE movie/{id}?deleteFiles=true` (no import exclusion); the movie's folder goes to `scan_dirs`.
- `web/unraid.py` — Unraid's GraphQL api (`POST /graphql`, `x-api-key`, a Viewer key; introspection is off, the schema is `api/generated-schema.graphql` in the unraid/api repo at the server's api version). Redirects aren't followed (Unraid with SSL sends http to its https address and a redirected POST becomes a GET): `UnraidRefused` says where to. `UnraidRefused`'s text is safe to show.
- `tautulli.py` / `web/seerr.py` — the one Tautulli (`tautulli_get(url, key, cmd)`, CLI too) and Seerr (`seerr_get(url, key, path)`) client every caller uses (watch history, stats, playback, status, connection Test). `tautulli.py` also has the history paging they share: `HISTORY_PAGE`, `PLAYS_OVERLAP`, `tautulli_after()`, `history_rows()`, `from_timestamp()`. A 401/403 or a non-success answer raises `TautulliRefused`/`SeerrRefused`, whose text is safe to show; requests' own errors still need redacting (Tautulli's key is a query param).
- `watch_history.py` — `WatchEvent`s (naive UTC) from Tautulli `get_history` (includes partial plays and all users, show TVDB id from `get_metadata` guids), falling back to Plex server history (completed plays only). Returns `None` on failure, and removers with `skip_if_watched_within` are then skipped. Events are matched to series by TVDB id, and by title only when the history has no TVDB id. Tautulli's `apikey` is a query param, so `requests` error text contains it: redact it before logging or storing any Tautulli error. `get_history`'s `after` is compared with each play's date in Tautulli's time zone, so every caller passes `tautulli_after(since)` (the day before) and checks exact times itself.
- `autoscan.py` — POSTs the old and new folders of moved media to Autoscan's `/triggers/manual`. Paths are sent as the *arr sees them; the rewrite on Autoscan's Plex target maps them to Plex paths and its `minimum-age` covers the async move.
- `plex.py` — fallback when Autoscan isn't configured: connects via plexapi and refreshes each library section collected from executed (non-dry-run) movers. Also `empty_plex_trash()` for `--empty-trash`: counts each movie/show section's trash via `/library/sections/{key}/all?type=<movie|episode>&trash=1` (includes old versions left by upgrades) and skips a section that is `refreshing` or over `[plex.empty_trash].max_items`, which guards against a missing mount trashing a whole library. Only then `list_trash()` fetches the items: Plex marks each trashed version (`Media`) with `deletedAt`, so an item with a live version is an upgrade leftover (only counted) and one without is fully deleted (`TrashedItem` in `result.trash`, listed on the run page). Fully deleted items are matched to the web app's removers by file name (`removed_files`, from `JobRunner.removed_files()`; sonarr and plex paths differ), and only unmatched ones count toward `max_deleted_items`. Its `dry_run` defaults to `[settings].dry_run`.
- `web/` — FastAPI app run by `main.py --serve` (one uvicorn worker on purpose: the scheduler will live in-process, no Redis). `create_app(settings, keys, run_job, load_config, run_scheduler, lookups)` is a factory; tests pass `keys` to replace the team's signing keys. Every page needs a sign-in, picked by `AUTH_MODE` (`WebSettings.auth_mode`): `password` (the app's own login, `web.login`) or `cloudflare` (Access); there is no mode without one.
  - `config_store.py` — `ConfigStore`: the config is `ConfigVersion` rows (`config_versions`, the newest is current; a restore saves an old document again) plus `ConfigSecret` rows (`config_secrets`, encrypted by `secret_box.SecretBox` with `HELPERR_SECRET_KEY` via HKDF + Fernet, never versioned, never rendered: forms are write-only, empty keeps the saved one). `save(document, by, note, expected_version, secrets)` refuses a document holding a secret (`config.document.secrets_in()`, versions are plain text), validates (with stand-in secrets), raises `ConfigConflict` when `expected_version` (0 = none yet, None = skip) isn't current, and turns auto-approve off for remover rules it changes or removes (noted in the version). `load_settings()` is what jobs run with (`app.state.load_config` unless a test passes one); an undecryptable secret raises `SecretError` saying to re-enter it. `web_defaults()` reads `[web]` without secrets, for the scheduler and plan expiry. `open_store()` is the CLI's way in (`main.load_settings()`): same db and migrations. A new install starts from `DEFAULT_DOCUMENT` (dry) and is set up on the Settings pages.
  - `lookups.py` — `Lookups` caches (10 min, cleared when a connection is saved) each arr's `ArrLibrary` (media `snapshot()`s, root folders, profiles, tag labels) and Plex's libraries, for the rule forms' pick lists and `preview_mover()`/`preview_profiler()` (whole library, earlier movers claim first, counts what's within `filter_time`; logs of `main` are silenced for that thread by `quiet()`). Snapshots matter: arrapi objects reload themselves from the api when an empty field is read (no certification) and tags/quality profiles only hold an id until read, one request per movie, so `arr_client.snapshot()` reads fields with `object.__getattribute__` and resolves tags/profiles from the fetched lists (`read_media()`, shared with movers and removers). `check_connection()` backs the Test buttons. Error text goes through `redact()` (Tautulli's key is a query param).
  - `settings.py` reads `AUTH_MODE` (`password`/`cloudflare`; unset means cloudflare when any `CF_ACCESS_*`/`ALLOWED_EMAILS` is set, so installs from before password mode keep working, else password), in cloudflare mode `CF_ACCESS_TEAM_DOMAIN`, `CF_ACCESS_AUD` and `ALLOWED_EMAILS` (empty in password mode), and `HELPERR_SECRET_KEY` (32+ chars, encrypts the config's secrets), and refuses to start if any the mode needs is missing or malformed, so auth can never be half configured. Optional `REMOVERS_ALLOW_APPLY` (`true`/`false`, default off) must be one of those when set.
  - `auth.py` is pure ASGI middleware that wraps every route (static files and 404s too) except `PUBLIC_PATHS` (`/healthz`) and `API_KEY_PATHS` (exact paths, `/webhooks/arr`), which check the app's API key themselves (`passed_through()`, shared by both modes). `PasswordMiddleware` (password mode) also lets `LOGIN_PATHS` (`/login`, `/setup`) and `/static/` through, reads the `helperr_session` cookie and `session_user()`s it in a thread; signed out, a page GET is redirected to `/login?next=` and everything else (the JSON API, posts) gets a 401. `AccessMiddleware` (cloudflare mode) verifies `Cf-Access-Jwt-Assertion` (RS256 only, keys from `https://<team>/cdn-cgi/access/certs`, issuer, audience, exp), then the email against `ALLOWED_EMAILS`. Denial reasons are logged (the path with `%r`, so a `%0A` can't forge a line in the Events page), never returned. Fails closed, including when Cloudflare's keys can't be fetched. Only `lifespan` scopes pass untouched; websockets are refused (the app has none).
  - `login.py` — password mode's login: one admin account, `login_username`/`login_password` (`hash_password()`: `scrypt$<log2 n>$<r>$<p>$<salt>$<hash>`, stdlib only) in `app_settings`. `LoginSession` rows (`login_sessions`) hold the sha256 of the cookie's random token, never the token; a session ends `SESSION_IDLE` (30 days) after last use (`last_seen_at` written at most `SESSION_TOUCH`, hourly) or `SESSION_MAX` (90 days) after signing in, and when the login changes. Until a password is set, `announce_setup_token()` (lifespan) writes a setup token to the log at every start (hash in `login_setup_token`), so only someone who can read the server's logs can create the login; `set_login()` uses it up and ends every session. `check_login()` does the same scrypt work for a wrong username. `change_password()` ends every other session. `reset_login()` (`main.py --reset-login`, run with `docker exec`, prints the token, never logs it) deletes the login and sessions; nothing on the web can reset it. `LoginThrottle` (`app.state.login_throttle`, in memory) refuses an address after `MAX_FAILURES` (5) wrong passwords/setup tokens within `FAILURE_WINDOW` (15 min), keyed by the connection's address only (never `X-Forwarded-For`, which anyone can make up), so behind a proxy everyone shares one count. `safe_next()` keeps `next` on this site.
  - `login_routes.py` — `/setup`, `/login`, `POST /logout` (404 in cloudflare mode) and Settings → Login (`/settings/login`: change password, `POST /settings/login/sign-out-others`, the reset command; in cloudflare mode it says Access signs you in). scrypt runs in a worker thread. The cookie is `HttpOnly`, `SameSite=Lax` (posts are covered by the Origin check) and `Secure` when the request is https or `X-Forwarded-Proto: https`; plain http on a LAN can't use Secure. Sign-in pages render `base.html` with `bare` (no sidebar, pill or badges: nothing about the setup before signing in); the header has a Sign out button in password mode.
  - `security.py` adds a strict CSP (no inline scripts/styles, no third-party content, so self-host any JS such as htmx) and other headers, and rejects non-GET requests whose `Origin` doesn't match `Host` (CSRF). It runs before auth. `API_KEY_PATHS` skip the Origin check, since they carry no browser cookies.
  - `jobs.py` — `JobRunner`: one worker thread runs queued `JobRun`s in order, so jobs never overlap (no locks needed). `submit()` refuses a job that is already queued/running (`AlreadyActive`). Each run calls `load_config()` (the store) fresh and then `main.run_job()`, with `config.force_dry_run()` when the run asked for dry run. A run can only force dry run on; making the config live is a settings change, which goes through a confirmation (`settings_routes.turns_live()`). Removers delete through `submit_apply()`, applying a reviewed removers plan (`JobRun.plan_run_id`, `approved`: `[{service, media_id, title, file_ids}]`, selected by `removal_key()` = `sonarr:<id>`/`radarr:<id>`, passed to `run_job` as `{"SONARR": {id: files}, "RADARR": ...}`). A removers run gets `movie_plays` only when Radarr has removers. It needs `REMOVERS_ALLOW_APPLY=true` (`WebSettings.allow_remover_apply`, an env var so the UI can never turn it on, checked again when the run executes), a finished non-apply removers run whose `approvable()` removals (`dry_run`/`blocked`) include every selected series, the plan under `WebDefaults.plan_max_age` (`defaults()`, 7 days by default), and no earlier apply of that plan. `apply_problem()` says why not; pages show it. Auto-approve is the other: `RemoverRuleSetting` rows (`remover_rule_settings`, keyed by `RemoverRule.key`) set on the Removers page; `auto_approved_rules()` returns their keys only when `allow_apply`, and `_execute` passes them as `auto_approve` only for a removers run that isn't forced dry and isn't applying a plan, so forced dry runs never delete. `routes.config_modes()` reports removers as partly live (None) when auto-approved rules would delete, so the job card, Run… confirmation and schedule form say so. A job's or run's mode has one name everywhere (`jobs.MODES`: dry run, live, live for some *arrs, plan for review, review with auto-approve, apply plan; the `_shell.html` `mode_tag` macro): `configured_mode()` for a job as configured, `run_mode()` for a run (forced dry, applying a plan, or the `mode` `_execute` stores in its result; older runs are read from their changes). Never call a mode "settings". `RunLogCapture` stores that run's log lines, filtered to the worker thread so request logs don't leak in. At startup, runs left queued/running are marked failed and never resumed (removers delete files). `wait_idle()` is for tests.
  - `scheduler.py` — `Scheduler` thread wakes a second into every minute and `tick(now)`s: each enabled `Schedule` whose cron has matched since `max(last_fired_at, updated_at, started_at)` is submitted to the `JobRunner` (trigger `schedule`, `JobRun.schedule_id` set). So missed times fire at most once, never for times before the app started or the schedule was last edited (an edit resets it). When clocks go back, the repeated wall time runs once, at its first occurrence (`cron.next_after_utc()`). `last_fired_at` is written before submitting; an `AlreadyActive` job skips that time. Tests pass `run_scheduler=False` to `create_app` and call `tick()` directly. Schedules are stored only in the database.
  - The scheduler also queues a follow-up empty trash (trigger `followup`) via `trash_followup_due()`, worked out from run history and `TrashEvent`s (`trash_events`, upgrades the webhook recorded) only: `followup_delay` after the last "work" (a live movers/removers run with a `done` move/remove, or an upgrade) not covered by the last `emptied()` run (config settings, nothing blocked/failed; a forced dry run doesn't count, a config-dry one does). An empty trash only covers work from `followup_delay` before it started, since Plex may not have scanned later work yet. A steady stream of work can delay it at most `FOLLOWUP_MAX_WAIT` delays after the first work since the last follow-up. Retried up to `followup_attempts` (0 = off), looking back `followup_lookback`, all from `WebDefaults` via `runner.defaults()`.
  - `webhooks.py` — `POST /webhooks/arr` for Radarr/Sonarr connect webhooks. `MovieAdded`/`SeriesAdd` call `JobRunner.submit_soon("movers", "webhook", "Radarr: Title (Year)")`, which reuses a queued run, or queues one more after a running one or a queued forced dry run (`_rerun`), so adds close together share a run. `Download` with `isUpgrade` (On File Upgrade) records a `TrashEvent` (pruned after `followup_lookback`) for the follow-up empty trash, never runs anything itself (Plex hasn't scanned yet). Other events return 200 and do nothing (so Radarr's Test works). The key comes from `X-Api-Key` or the basic auth password, never the URL, compared with `hmac.compare_digest`. The app's API key is an `AppSetting` (`app_settings` key/value table, also for future UI-edited defaults), generated at startup when missing and shown in plain text on `/settings/webhook` like the *arrs, since it only starts movers. A key that unlocks more (e.g. the JSON API, which can approve deletes) should get separate keys with explicit scopes, not this one.

## Notes

- Code uses Python 3.14 syntax, e.g. unparenthesized multi-exception `except A, B:` in `plex.py` (PEP 758) — this is intentional, not a bug.
- `main()` takes `argv` (tests call `main.main([])` so pytest's argv isn't parsed).
- New settings go in the document (and a settings form); keep the README config tables in sync when adding fields, and add a secret to `SECRET_FIELDS` (plus a masked `__repr__`).
- `DATA_DIR` (set to `/config` in the Dockerfile) moves `helperr.db` and `logs/` out of the code dirs; unset, they stay at the repo root. Docker can't mount over `/app/config` because that's the config Python package.
- `.github/workflows/docker.yml` runs the tests, then builds the image `ghcr.io/ryanthornburg/plex-library-helperr`: pushes to `mainline` publish `edge` and `sha-<commit>`; a release tag `vX.Y.Z` publishes `X.Y.Z`, `X.Y`, `X`, `latest` and `sha-<commit>` (a pre-release `vX.Y.Z-rc.1` only its own tag), after checking the tag matches `pyproject.toml`'s version, then a `release` job makes the GitHub release from that version's `CHANGELOG.md` section (`## X.Y.Z (date)`). Unraid's web container pulls `edge`, so every push to mainline deploys (CA Auto Update at 06:00, or a Force Update): keep mainline releasable. Push a release's commit and tag together (`git push origin mainline vX.Y.Z`), so the edge build's `git describe` already sees the tag.
- Versions: SemVer from `2.0.0` (the web app; `1.x` was the script). `pyproject.toml` holds it (bump it, run `uv lock`, add the CHANGELOG section, commit, push, then tag; `tests/test_version.py` checks the lock and the changelog agree). Major = an upgrade needs the user to do something (new required env var, a removed feature, a breaking config/API change); a migration that runs itself isn't one. `version.py`'s `VERSION` is the image's `HELPERR_VERSION` build arg (CI's `git describe`: `2.0.0`, or `2.0.0-3-gabc1234` for edge), else pyproject's with `-dev`; it's at the bottom of the sidebar (`APP_VERSION` Jinja global) and in the startup logs, never on public paths (`/healthz`, sign-in pages).
- Branches: work happens on `mainline`. The web app was developed on a `v2` branch and merged into `mainline` on 2026-11-10 (fast-forward); the `v2` branch is retired and no longer builds. The command line script that read `config.toml` (version 1) is sunset: its last commit is tagged `v1` (image `sha-b421917`) and it gets no more fixes. Actions are pinned to commit SHAs (with the version in a comment) and Dependabot updates them along with uv and the base images. README screenshots (`docs/screenshots/`) use made-up data only, never the real library or users.
- `.dockerignore` is an allowlist so local files (a dev `helperr.db`, logs, a leftover `config/config.toml` with real keys) never reach the build context. When adding a module outside the top level, `config/` included (each file is listed), add it there and to the Dockerfile's `COPY` lines; `web/` is copied whole. Building the image and running it `--read-only` catches a missed one.
